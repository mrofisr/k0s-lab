# k0s learning lab

A reproducible single-node Kubernetes lab on this Ubuntu 24.04 arm64 host
(`10.0.0.81`). It teaches the CNI, metrics, certificate, and service-mesh
layers one at a time:

- **k0s** as the Kubernetes distribution.
- **Cilium** as the CNI, now replacing kube-proxy with its eBPF datapath.
- **metrics-server** from k0s, verified with `kubectl top`.
- **cert-manager** with a private CA and a `demo.local` certificate.
- **Istio** in ambient mode, exposed on NodePorts `30080`/`30443`.
- **Skopos** `v0.0.1-alpha`, installed in `observability` on local-path storage.

Caddy keeps host ports `80` and `443`. Nothing in this lab binds those ports.

## Stack

| Component | Version | Notes |
| --- | --- | --- |
| k0s | `v1.36.6+k0s.0` | Single controller+worker, no taints |
| k0sctl | `v0.33.1` | Installs k0s over SSH |
| Cilium | `1.20.4` | Kubernetes IPAM, VXLAN, kube-proxy replacement active |
| metrics-server | `v0.9.0-k0s.2` | Built into k0s |
| cert-manager | `v1.21.3` | Self-signed bootstrap Issuer → private CA |
| Istio | `1.32.0` | Ambient profile, ztunnel, NodePort ingress |
| Skopos | `0.0.1-alpha` | Gateway, ClickHouse, collector, OBI |
| Demo app | `traefik/whoami:v1.11.0` | Prints request headers and peer metadata |

The versions are pinned deliberately. Cilium 1.20 is tested through Kubernetes
1.36; k0s 1.37 is newer than that tested range. Istio 1.32 passed
`istioctl x precheck` against this cluster.

## Design choices

- **Single node first.** Multi-node adds Cilium routing, etcd quorum, and
  scheduling variables before the core stack is understood. Add workers later.
- **Cilium phase 2 replaces kube-proxy.** Phase 1 kept kube-proxy for a
  lower-risk start. Cilium now owns ClusterIP, NodePort, LoadBalancer, and
  HostPort service handling. `socketLB.hostNamespaceOnly=true` and
  `cni.exclusive=false` keep the datapath compatible with Istio.
- **Istio ambient now.** Phase 1 used sidecars for a predictable first install.
  The demo namespace now runs without sidecars; ztunnel handles HBONE and mTLS,
  while the ingress gateway remains a classic Envoy proxy.
- **NodePort ingress.** `30080`/`30443` are deterministic and leave Caddy on
  `80`/`443` untouched.
- **Private CA.** No public DNS or ACME dependency; cert-manager still exercises
  the full Issuer → Certificate → Secret → Gateway flow.
- **Persistent host install.** k0s runs as a systemd service and survives a
  reboot. The lab directory is Git-tracked.

## Prerequisites

- Ubuntu 24.04 arm64, at least 4 vCPU and 8 GiB RAM.
- Passwordless sudo for the lab user.
- SSH access to `ubuntu@10.0.0.81` with `~/.ssh/k0s-lab`.
- These binaries in `~/.local/bin`: `k0sctl`, `kubectl`, `helm`, `istioctl`.
- Caddy may own `80`/`443`; this lab does not use them.

The host already has `export PATH="$HOME/.local/bin:$PATH"` in `~/.bashrc` and
`~/.profile`.

## Quick start

```sh
cd "$HOME/Documents/projects/k0s-lab"
source scripts/env.sh
./scripts/install.sh
```

The script is idempotent. It installs the firewall unit, applies k0s, installs
Cilium, waits for the node, installs cert-manager, creates the CA chain,
installs ambient Istio, patches the ingress NodePorts, deploys the demo, adds
`demo.local` to `/etc/hosts`, and runs the smoke tests. On an upgrade from the
phase-1 layout it removes kube-proxy and its iptables chains only after Cilium
reports `KubeProxyReplacement: True`.

On a fresh install the script also seeds `~/.kube/config` when it has no
contexts, so a plain `kubectl get nodes` works. If you already use
`~/.kube/config` for other clusters, it leaves the file alone; select the lab
context explicitly:

```sh
source "$HOME/Documents/projects/k0s-lab/scripts/env.sh"
```

## What each phase does

### 1. k0s

```sh
k0sctl apply --config config/k0sctl.yaml \
  --kubeconfig-out "$HOME/.kube/k0s-lab.conf"
export KUBECONFIG="$HOME/.kube/k0s-lab.conf"
```

`config/k0sctl.yaml` installs the k0s binary at
`/home/ubuntu/.local/bin/k0s` and runs one controller with an embedded worker.
The API server listens on `10.0.0.81:6443`.

The node stays `NotReady` until a CNI exists. That is expected.

### 2. Host firewall

The host's INPUT chain rejects everything except SSH, HTTP, HTTPS, and one
local port. Kubernetes pods must reach host services such as the API server
(`6443`), kubelet (`10250`), and Hubble peer (`4244`). The unit inserts:

```sh
iptables -I INPUT 1 -s 10.244.0.0/16 -j ACCEPT
```

It is enabled at boot and ordered before `k0scontroller.service`.

### 3. Cilium

```sh
helm repo add cilium https://helm.cilium.io/
helm repo update
helm upgrade --install cilium cilium/cilium --version 1.20.4 \
  --namespace kube-system -f cilium/values.yaml --wait
```

Key values:

- `ipam.mode=kubernetes` — Cilium uses the node's `podCIDR` (`10.244.0.0/24`).
- `kubeProxyReplacement=true` — Cilium's eBPF datapath owns service handling.
- `k8sServiceHost=10.0.0.81` / `k8sServicePort=6443` — direct API path once
  kube-proxy is gone.
- `socketLB.hostNamespaceOnly=true` — keeps socket load balancing out of pod
  namespaces so Istio redirection still sees the original ClusterIP.
- `cni.exclusive=false` — allows the Istio CNI plugin to chain with Cilium.
- `bpf.masquerade=false` — required for Istio ambient; iptables masquerading
  remains in use.
- `MTU=1500` — the host NIC reports MTU 9000, but lab clients use 1500.
  The Cilium chart key is uppercase; lowercase `mtu` is silently ignored.
- `operator.replicas=1` — a single-node lab does not need two operators.
- Hubble relay and UI are enabled for flow observation.

Phase 1 kept kube-proxy. The migration, verification, and rollback steps are in
[docs/phase2-kube-proxy.md](docs/phase2-kube-proxy.md).

Verify:

```sh
kubectl get nodes
kubectl -n kube-system exec ds/cilium -- cilium-dbg status --brief
kubectl -n kube-system exec ds/cilium -- cilium-dbg status | grep KubeProxyReplacement
kubectl -n kube-system exec ds/cilium -- cilium-dbg service list | grep -E '10.96.0.1|30080|30443'
```

### 4. metrics-server

k0s installs metrics-server as a core component; there is no separate chart.
After the firewall rule exists:

```sh
kubectl top nodes
kubectl top pods -A
```

If `kubectl top nodes` says `Metrics API not available` for the first few
seconds, wait or restart the metrics-server pod. `kubectl top pods` working is
the stronger signal that kubelet scraping and the metrics APIService are both
healthy.

### 5. cert-manager

```sh
helm repo add jetstack https://charts.jetstack.io/
helm repo update
helm upgrade --install cert-manager jetstack/cert-manager \
  --namespace cert-manager --create-namespace --version v1.21.3 \
  --set crds.enabled=true --wait

kubectl apply -f cert-manager/selfsigned-issuer.yaml
kubectl apply -f cert-manager/ca-certificate.yaml
kubectl -n cert-manager wait --for=condition=Ready certificate/lab-ca --timeout=180s
kubectl apply -f cert-manager/ca-clusterissuer.yaml
```

The chain is:

```text
Issuer/lab-selfsigned (self-signed)
  └── Certificate/lab-ca (isCA, secret lab-ca-key-pair)
        └── ClusterIssuer/lab-ca
              └── Certificate/demo-local (secret demo-local-tls)
```

The `demo-local` Certificate lives in `istio-system` because an Istio ingress
gateway reads `credentialName` from its own namespace.

### 6. Istio ambient

The ambient profile installs Istiod, the CNI node agent, and ztunnel, but it
does **not** include an ingress gateway. Enable the gateway in the same overlay
so the existing NodePort service is not pruned:

```sh
istioctl install -y --set profile=ambient \
  --set 'components.ingressGateways[0].enabled=true' \
  --set 'components.ingressGateways[0].name=istio-ingressgateway' \
  --set values.gateways.istio-ingressgateway.type=NodePort

kubectl -n istio-system patch svc istio-ingressgateway --type=strategic \
  -p '{"spec":{"type":"NodePort","ports":[{"port":80,"nodePort":30080},{"port":443,"nodePort":30443}]}}'
```

The patch preserves the default `status-port` and target ports, and pins only
the HTTP/HTTPS NodePorts. The CNI agent chains `istio-cni` after `cilium-cni` in
`/etc/cni/net.d/05-cilium.conflist`; Cilium's `cni.exclusive=false` is what
allows this. See [docs/phase2-ambient.md](docs/phase2-ambient.md) for the
migration and rollback.

### 7. Demo

```sh
kubectl apply -f istio/demo-namespace.yaml
kubectl label namespace demo istio-injection- --overwrite 2>/dev/null || true
kubectl apply -f apps/whoami.yaml
kubectl apply -f cert-manager/demo-certificate.yaml
kubectl apply -f istio/gateway.yaml
kubectl apply -f istio/virtualservice.yaml
kubectl apply -f istio/peer-authentication.yaml
kubectl -n demo rollout restart deploy/whoami
kubectl -n demo rollout status deploy/whoami --timeout=300s
```

The namespace label `istio.io/dataplane-mode=ambient` puts whoami in ambient
mode; the pod has no `istio-proxy` sidecar. If upgrading from sidecars, remove
the old injection label and restart the deployment. There are two Gateways:

- `demo-gateway-http` on port 80, used only by the redirect VirtualService.
- `demo-gateway-https` on port 443, with `credentialName: demo-local-tls`.

The redirect uses an explicit `authority: demo.local:30443`. Istio's built-in
`httpsRedirect` copies the incoming Host header, which would produce the wrong
port behind a NodePort. The full ambient migration and rollback are in
[docs/phase2-ambient.md](docs/phase2-ambient.md).

Finally:

```sh
echo '10.0.0.81 demo.local' | sudo tee -a /etc/hosts
kubectl -n cert-manager get secret lab-ca-key-pair \
  -o jsonpath='{.data.tls\.crt}' | base64 -d > cert-manager/lab-ca.crt
```

## Verify

```sh
kubectl get nodes -o wide
kubectl top nodes
kubectl top pods -A
kubectl -n kube-system exec ds/cilium -- cilium-dbg status --brief
kubectl -n kube-system exec ds/cilium -- cilium-dbg status | grep KubeProxyReplacement
kubectl -n kube-system get ds kube-proxy
istioctl proxy-status
istioctl ztunnel-config workloads | grep whoami
istioctl analyze -n demo
```

Expected: the node is `Ready` with role `control-plane`; `top` returns CPU and
memory; Cilium reports `OK` and `KubeProxyReplacement: True`; the kube-proxy
DaemonSet is absent; `istioctl proxy-status` lists the ingress gateway and
ztunnel (there is no whoami sidecar); ztunnel reports `PROTOCOL HBONE` for
whoami; analyze reports no validation issues.

Ingress:

```sh
curl -I http://demo.local:30080
curl --cacert cert-manager/lab-ca.crt https://demo.local:30443/
```

The HTTP request returns `301` to `https://demo.local:30443/`. The HTTPS
request returns `200` and whoami prints the request headers.

### mTLS proof

`istio/peer-authentication.yaml` sets `STRICT` mTLS in the `demo` namespace. In
ambient mode the whoami pod has no sidecar, so there is no
`X-Forwarded-Client-Cert` header. Inspect ztunnel instead:

```sh
istioctl ztunnel-config workloads | grep whoami
istioctl ztunnel-config connections
```

The workload is `PROTOCOL HBONE`, and the connection table shows an inbound
HBONE connection from `istio-ingressgateway` to whoami. That is the mTLS path.

To see STRICT enforcement, run a non-ambient pod and call whoami directly:

```sh
kubectl -n default run nettest --image=curlimages/curl:8.11.0 --restart=Never --command -- \
  curl -sS --max-time 5 http://whoami.demo.svc.cluster.local/
kubectl -n default logs nettest
kubectl -n default delete pod nettest
```

The call is reset because the source has no mesh certificate.

## Troubleshooting

**CoreDNS returns 503, metrics-server crashloops, or `kubectl logs` says
`No agent available`.**

These are all symptoms of pods not reaching host services. Check the firewall:

```sh
sudo iptables -C INPUT -s 10.244.0.0/16 -j ACCEPT || sudo ./scripts/firewall.sh
```

Then restart metrics-server to clear its backoff:

```sh
kubectl -n kube-system delete pod -l k8s-app=metrics-server
```

**HTTP redirect points at `:30080`.**

The redirect authority is hard-coded for the NodePort mapping. If you change
the ports, update `istio/virtualservice.yaml` as well.

**`kubectl top nodes` says `Metrics API not available`.**

Wait 30 seconds. If it persists:

```sh
kubectl -n kube-system rollout restart deploy/metrics-server
kubectl -n kube-system rollout status deploy/metrics-server
```

**Cilium pods are Pending.**

Check node taints. A controller-only node with a `NoSchedule` taint needs
`noTaints: true` or a toleration. This lab sets `noTaints: true`.

**Hubble relay is not Ready after a Cilium restart.**

The relay can keep a stale Hubble peer connection. Restart it:

```sh
kubectl -n kube-system rollout restart deploy/hubble-relay
kubectl -n kube-system rollout status deploy/hubble-relay
```

**Changing MTU after installation.**

The agent reads `MTU` at startup. After editing `cilium/values.yaml` and running
`helm upgrade`, restart the DaemonSet so the devices are updated:

```sh
kubectl -n kube-system rollout restart ds/cilium
```

Cilium's endpoint MTU updater then adjusts existing pod interfaces. Verify with
`ip link show cilium_vxlan` on the host and with `ip route` inside a pod.

**The ingress is unreachable from another machine.**

Confirm the client can reach `10.0.0.81:30080` and `10.0.0.81:30443`. On a cloud
VM, also check the VCN security list; the host firewall is not the only layer.

**`kubectl` tries `localhost:8080`.**

No usable kubeconfig was found. Select the lab context:

```sh
source "$HOME/Documents/projects/k0s-lab/scripts/env.sh"
# or:
export KUBECONFIG="$HOME/.kube/k0s-lab.conf"
```

**`demo.local` resolves to the wrong address.**

Remove stale `/etc/hosts` entries and keep exactly:

```text
10.0.0.81 demo.local
```

## Teardown

```sh
./scripts/teardown.sh          # prompts
./scripts/teardown.sh --yes    # no prompt
```

The script removes the demo, Istio, cert-manager, Cilium, k0s, the firewall
unit, the `/etc/hosts` line, and the k0s kubeconfig. It does not delete the
repository files or the CLIs in `~/.local/bin`.

To remove only the demo app while keeping the platform:

```sh
kubectl delete -f istio/virtualservice.yaml
kubectl delete -f istio/gateway.yaml
kubectl delete -f istio/peer-authentication.yaml
kubectl delete -f cert-manager/demo-certificate.yaml
kubectl delete -f apps/whoami.yaml
kubectl delete -f istio/demo-namespace.yaml
```

## Skopos on k0s

The published `v0.0.1-alpha` chart runs in the `observability` namespace:

```sh
./scripts/install-skopos.sh
```

The script installs the local-path provisioner if needed, applies the pinned
release values, and waits for the data plane. Do not add `--wait` to the Helm
command: the ClickHouse schema and gateway user are created by a post-install
hook, while the gateway readiness probe depends on them; `--wait` deadlocks.

Verify:

```sh
kubectl -n observability port-forward svc/skopos-gateway 8080:8080
curl -sS http://127.0.0.1:8080/readyz
curl -sS 'http://127.0.0.1:8080/api/v1/query?query=target_info'
```

See [docs/skopos-on-k0s.md](docs/skopos-on-k0s.md) for the install, the OBI
capability findings, the k3d comparison, and uninstall.

handling, and k0s kube-proxy is disabled and removed. The migration,
verification, and rollback commands are in
[docs/phase2-kube-proxy.md](docs/phase2-kube-proxy.md).

**Phase 2b: Istio ambient mode — complete.** The `demo` namespace runs without

**Add a worker.** Add a second host to `config/k0sctl.yaml` with role
`worker`, then re-apply. This is the point where Cilium routing, pod CIDR

**Observe traffic.** Open Hubble:

```sh
kubectl -n kube-system port-forward svc/hubble-ui 12000:80
```

Then browse `http://127.0.0.1:12000`.

## Notes and caveats

- The k0s binary lives at `/home/ubuntu/.local/bin/k0s` and is root-owned
  (`0755`). Do not move or delete it while the cluster is running. Keep
  `/home` on the root filesystem, or k0s will not start at boot.
- The CA private key stays in the cluster Secret
  `cert-manager/lab-ca-key-pair`. Only the public certificate is exported.
- Cilium replaces kube-proxy and the demo namespace runs in Istio ambient mode.
  Keep one layer per change; switch a single namespace when testing sidecar vs
  ambient.
- The ambient profile omits the ingress gateway; the install overlay enables it
  so the NodePort service is not pruned.
- `/etc/cni/net.d/05-cilium.conflist` must list `cilium-cni` then `istio-cni`.
  Cilium's `cni.exclusive=false` is what prevents Cilium from removing the
  Istio plugin.
- k0s leaves an existing kube-proxy DaemonSet in place when
  `kubeProxy.disabled` is switched on. The install script removes it only after
  Cilium reports `KubeProxyReplacement: True`.
- The host NIC reports MTU 9000. Cilium is pinned to 1500 so clients on the
  local LAN do not depend on end-to-end jumbo-frame support.
- This lab is separate from the Skopos repository. Installing Skopos on top is
  an optional next step, not part of the bootstrap.
